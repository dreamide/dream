# v0.26.0 performance review

Recovered from the October 5, 2026 architecture report. The original ranking was
based on code paths, without profiling. Later session measurements are scoped
synthetic or local measurements, not end-to-end latency guarantees.

## PERF-01: One transcript writer per agent turn

Original problem: host step saves and renderer finish saves replace whole
transcripts. A host-owned writer should persist changed rows, with the renderer
stopping redundant saves for host-run turns.

Shipped: 55c2efc saves the request once, then the active assistant row; catalog
writes skip unchanged rows and the queue preserves the starting index.

Completion scope: changed-row writes, identical-save no-ops, and queued full/tail
ordering. Existing catalog-store, state-save-queue, and chat-turn-route checks
cover those behaviors.

Deferred: renderer finish saves remain. Removing them also requires host-owned
metadata and durable user answers; this was deliberately excluded after review.

## PERF-02: Live-transcript view model

Original problem: SDK snapshots replace every part identity each tick, causing
settled chips and whole-transcript summaries to redo work.

Shipped: c7a85a7 structurally shares unchanged parts and incrementally derives
todo summaries and token estimates. Relevant owners are `chat/stable-messages.ts`,
`chat/todo-list.ts`, and `chat/message-token-estimate.ts`.

Completion scope: reused settled parts, changed-part updates, mutable SDK inputs,
and append/reset handling. Existing stable-messages checks exercise identity and
mutation cases. Recorded synthetic scans fell from 4.6 to 0.5 ms for 200 messages
and a 150-tool live turn.

Deferred: a unified visibility/throttle policy and React render-count measurement
were not established by that commit; visibility gating shipped in PERF-04.

## PERF-03: Per-repository Git context

Original problem: each host entry point independently rediscovers repository
facts; a refresh fans out to many Git processes. Optimizing status alone is only
part of this candidate.

Shipped: be9f9a8 introduces `electron/api/project-git/repository-context.js` and
routes the Git runner through it.

Completion scope: stable root/remote/default-branch facts cached, simultaneous
volatile reads shared, summary served from full status, invalidation around
writes, and external changes visible on the next volatile read. Existing context
and real-repository status checks cover these contracts. A warmed local refresh
used 6 processes instead of 18; a cold refresh used 9.

Deferred: no persistent filesystem watcher; stable facts expire according to
the repository context policy. Broader per-repository write serialization was
not part of the delivered read optimization.

## PERF-04: One project-resource cache

Original problem: roughly twelve readers own five different caches, independently
interpreting refresh keys and repeating file lists and Git requests.

Shipped: d9f5ee6 moves readers onto `src/lib/project-resource-cache.ts` and
`src/components/ide/project-resources.ts`.

Completion scope: keys include host and project, identical in-flight reads join,
compatible full/summary and file-limit reads share results, invalidation refreshes
visible subscribers, and inactive readers do not fetch. Existing fake-loader
checks cover the cache and resource layer; consumers retain their visible behavior.

## PERF-05: CLI catalog

Original problem: readiness, launch, version, and usage paths repeat discovery
under different policies; each Windows path lookup spawns PowerShell.

Shipped: 73dc798 centralizes discovery, versions, derived facts, and usage reads.

Completion scope: found/missing TTLs, in-flight sharing, errors not retained,
forced refresh, and forgetting facts after upgrades/start failures. Existing
cli-catalog checks use injected readers and a clock. Recorded readiness/path
lookups fell from about 500 ms to 240 ms cold, then cache hits on warm turns.

## PERF-06: Store save scheduler and worker reads

Original problem: an effect in IdeShell sends encoded whole-state saves after
slice changes; workspace reads still block the main process.

Shipped: 76510de adds the save scheduler, incremental workspace changes, and
ordered worker-backed loads.

Completion scope: dirty slices grouped, debounce/idle scheduling, close flush,
failed saves retried, unloaded SSH catalogs preserved, and loads follow queued
writes. Existing save-scheduler, workspace-save, and queue checks cover the seam.
A synthetic 30-project/600-chat view edit fell from about 181,000 to 830 payload
characters.

Deferred: project/chat changes still encode the workspace before diffing it;
the delivered improvement reduces IPC and writes, not every encoding cost.

## PERF-07: Shared turn-output stage

Original problem: batching depends on provider delta IDs while the registry keeps
all chunks and the observer clones large messages for each chunk. The original
proposal also suggested bounded replay snapshots, marked speculative.

Shipped: 81e40e7 adds `electron/api/chat/turn-output.js` behind the writer.

Completion scope: consecutive same-part plain deltas coalesced for every adapter,
50 ms maximum delay, ordering preserved across boundaries, metadata passed intact,
and flush on finish. Existing output-stage and writer checks cover the contracts.
With 60 tool calls of 20 KB plus 1,500 deltas, recorded named-delta observer CPU
fell from 2,515 to 750 ms; wall time remained about 23 seconds.

Deferred: bounded message-so-far reconnect replay was explicitly not built.
It changes the host-socket resume contract and needs a separate task.
