## SSH-PROMPT: SSH prompts belong to their connection attempt

Status: implemented

Problem: concurrent foreground connections share one prompting slot, so a
helper can label its question with another Host and cancel that other attempt.

Scope: the SSH connection module owns prompt attribution and retirement.
Carry an opaque attempt identity through the existing helper roundtrip. Reject
late questions and answers after cancellation, replacement or disconnection.
Keep the window prompt broker, silent background probes, and route supervision.

Completion criteria:

- Overlapping connections cannot borrow each other's prompt attribution.
- Declining a question cancels only its originating attempt.
- Replaced/disconnected attempts cannot publish or consume late answers.
- Existing SSH, askpass, broker and desktop checks pass.

Validation: existing SSH connection, askpass, prompt broker, SSH arguments and
desktop handler selection: 5 files passed, 29 checks passed and 1 skipped.
Typecheck and diff whitespace checks passed. No tests were added.

Remaining/deferred: no implementation remaining. Real concurrent SSH prompts
were not exercised; the existing checks do not reproduce that interleaving.
The window broker still presents already-issued questions until answered or
timed out; a retired attempt ignores the answer and settles its helper early.

## SAVED-ROUTES: Saved host connection edits own their lifetime

Status: implemented

Problem: route verification awaits desktop work while route limits, connection
existence, replacement credentials and cleanup are coordinated independently.

Scope: concentrate saved-connection mutation lifetime and acceptance rules in
one module. Verify against current state before publishing; retire resources
from edits that no longer apply. Cover pairing, SSH additions, route edits,
authenticated merging, target changes and connection removal. Preserve the
Desktop bridge, route supervisor, Connection recovery, identity checks and
existing route limit. Do not replay writes or change pairing behavior.

Completion criteria:

- Concurrent edits cannot exceed the route limit or restore removed records.
- Superseded verification leaves no SSH setting or newly acquired credential.
- Replaced/removed credentials are retired without retiring a current one.
- Record publication, persistence and reconnect ordering have one owner.
- Relevant existing host, route, persistence and type checks pass.

Implementation: `store/saved-host-connection-edits.ts` owns pairing, route
addition/replacement/removal, SSH target edits, authenticated merging and
connection removal. Accepted changes invalidate outstanding verification;
identity revisions also prevent late pairing from restoring a newly removed
Host. Credential retirement checks current references and runs even when
reconnect fails. Connection recovery remains with its existing owner.

Validation: 28 existing checks across 5 host-action, connection-follow,
catalog-load, recovery and desktop-handler files passed. Typecheck, changed
file formatting/lint and diff whitespace checks passed. No tests added.

Remaining/deferred: no implementation remaining. Existing checks do not
directly exercise overlapping route edits; no live pairing or SSH verification
was performed.

## ATTACHMENT-LIFETIME: Chat attachment files own preparation and release

Status: implemented

Problem: adapters release only already-prepared files, so cancellation during
preparation and partial preparation failures can leave temporary files behind.

Scope: the attachment module owns preparation and release through turn
settlement. Absorb shared file handling from the Codex prompt module and remove
per-adapter cleanup choreography. Preserve temporary files for Codex,
OpenCode and ACP, chat-lived files for Claude, provider-specific image delivery
and permissions, session reconstruction and durable turn completion.

Completion criteria:

- Stop during preparation and failed preparation release temporary files.
- Normal completion releases temporary files; observer disconnect does not.
- Every attachment-consuming adapter uses the owning lifetime consistently.
- Claude retains its existing chat-file repair, sweep and follow-up behavior.
- Relevant existing attachment, provider, turn and type checks pass.

Implementation: `host/chat-attachments.js` owns temporary preparation and
release around provider execution, wired by the Agent turn module. Codex,
OpenCode and ACP (Cursor/Grok) receive prepared attachment descriptions and
hold no cleanup callbacks. Partial writes and cancellation reach the same
awaited release. `shared/attachment-content.js` owns decoding, naming and
prompt descriptions, also used by Claude's unchanged chat-lived cache.
Antigravity's existing text-only prompt translation remains unchanged.

Validation: `pnpm check` passed scratch hygiene, lint, typecheck and all 203
test files (1,400 checks passed, 7 skipped). After the final import/abort
cleanup, the 24 chat/attachment files passed again (184 checks), along with
typecheck, changed-file lint and diff whitespace checks. No tests were added.

Remaining/deferred: no implementation remaining. Making other providers'
attachments chat-lived is a separate behavior decision. No live provider or
filesystem fault-injection walkthrough was run; release failures caused by
the filesystem are retried and reported as warnings.
